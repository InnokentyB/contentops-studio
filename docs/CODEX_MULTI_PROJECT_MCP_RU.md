# Разделение проектов ContentOps Studio в Codex

## Зачем это нужно

MCP-токен ContentOps Studio привязан к конкретному проекту и роли. Один глобальный
токен в `~/.codex/config.toml` нельзя использовать для нескольких проектов: Codex
может открыть правильную рабочую папку, но получить контекст другого проекта.

Правильная схема:

- в глобальном `~/.codex/config.toml` нет подключения ContentOps Studio;
- в корне каждого проекта есть собственный `.codex/config.toml`;
- конфигурация содержит только имена переменных окружения, но не токены;
- токены хранятся локально в `~/.codex/.env` с правами `600`;
- для каждой роли и каждого проекта выпускается отдельный project-scoped токен.

## Структура

Для AnalystCraft используется каталог:

```text
/Users/innokentyb/AnalystCraft
```

Для HireWire используется каталог:

```text
/Users/innokentyb/Documents/Product/hirewire-marketing
```

В каждом каталоге `.codex/config.toml` объявляет семь подключений:

- `contentops_strategist`;
- `contentops_planner`;
- `contentops_writer`;
- `contentops_editor`;
- `contentops_art_director`;
- `contentops_publisher`;
- `contentops_growth_analyst`.

Все подключения используют `bearer_token_env_var` и `required = true`. Если ключ
отсутствует, Codex останавливает подключение вместо работы без нужной изоляции.

## Настройка второго устройства

1. Добавьте в Codex два отдельных проекта, указав точные каталоги из раздела выше.
2. Выпустите в ContentOps Studio новые токены для этого устройства. Не переносите
   действующие токены с первого компьютера.
3. Запишите токены в `~/.codex/.env` под именами, указанными в проектных
   `.codex/config.toml`.
4. Ограничьте доступ к файлу командой `chmod 600 ~/.codex/.env`.
5. Полностью перезапустите Codex, чтобы он перечитал конфигурацию и окружение.
6. В начале новой задачи вызовите `ba_get_agent_workspace_manifest` и проверьте
   ожидаемые `project.id` и `project.slug`.

Ожидаемые границы:

| Проект | `project.id` | `project.slug` |
| --- | ---: | --- |
| AnalystCraft | 10 | `analystcraft-2` |
| HireWire | 29 | `hirewire` |

Если manifest вернул другой проект, работу необходимо остановить. Сервер также
отклоняет явный запрос к проекту, который не совпадает с привязкой токена, с
ошибкой `MCP_PROJECT_SCOPE_MISMATCH`.

## Безопасность

- Не добавляйте `~/.codex/.env` или значения токенов в Git.
- Не используйте один токен для разных ролей, проектов или устройств.
- При потере устройства отзовите только его токены в настройках ContentOps Studio.
- Не передавайте `projectId` другого проекта в обход manifest: сервер отклонит запрос.
