# Разделение проектов ContentOps Studio в Codex

## Зачем это нужно

MCP-токен ContentOps Studio привязан к конкретному проекту и роли. Одна глобальная
connection плагина ContentOps Workspace рассчитана на один проект: Codex разделяет
её между задачами, поэтому повторная авторизация меняет подключение сразу для всех
проектов. Сервер правильно отклоняет такой конфликт как `MCP_PROJECT_SCOPE_MISMATCH`.

Правильная схема:

- в глобальном `~/.codex/config.toml` нет подключения ContentOps Studio;
- каждый Planner-проект добавлен в Codex как отдельный сохранённый проект с собственным каталогом;
- в корне каждого каталога есть собственный `.codex/config.toml`;
- конфигурация содержит только имена секретов, но не токены;
- токены хранятся локально в `~/.codex/.env` с правами `600`;
- для каждой роли и каждого проекта выпускается отдельный project-scoped токен.
- имена MCP-серверов и env-переменных содержат slug и ID проекта и поэтому не пересекаются.

Не создавайте семь ролей как projectless-задачи Codex: они не наследуют проектный
`.codex/config.toml` и снова попадают в общую connection плагина.

## Структура

Для AnalystCraft используется каталог:

```text
/Users/innokentyb/AnalystCraft
```

Для HireWire используется каталог:

```text
/Users/innokentyb/Documents/Product/hirewire-marketing
```

В каждом каталоге `.codex/config.toml` объявляет семь подключений с отдельным
namespace. Например, для проекта `analystcraft-2`, ID 10:

- `contentops_analystcraft_2_p10_strategist`;
- `contentops_analystcraft_2_p10_planner`;
- `contentops_analystcraft_2_p10_writer`;
- `contentops_analystcraft_2_p10_editor`;
- `contentops_analystcraft_2_p10_art_director`;
- `contentops_analystcraft_2_p10_publisher`;
- `contentops_analystcraft_2_p10_growth_analyst`.

Planner генерирует точные имена, готовый `.codex/config.toml` и блок секретов при
выпуске или ротации «7 ролей». Не переименовывайте их вручную.

Все подключения используют `bearer_token_env_var` и `required = true`. Локальный
login-agent macOS загружает ключи из `~/.codex/.env` в окружение приложений при
входе в систему. Если ключ отсутствует, Codex останавливает подключение вместо
работы без нужной изоляции.

## Настройка второго устройства

1. В Planner выберите нужный проект и откройте **Настройки → MCP → Персональные доступы**.
2. Выпустите или ротируйте пакет «7 ролей» для этого устройства. Не переносите
   действующие токены с первого компьютера.
3. Создайте каталог с именем, которое показал Planner, и сохраните выданный блок
   в `<каталог>/.codex/config.toml`.
4. Добавьте выданный блок секретов в `~/.codex/.env` и ограничьте доступ к файлу
   командой `chmod 600 ~/.codex/.env`.
5. Из репозитория ContentOps Studio запустите
   `./scripts/install_contentops_codex_env_macos.zsh`. Скрипт установит login-agent,
   который переносит все ключи `CONTENTOPS_*_TOKEN` в окружение macOS и не пишет
   их значения в журнал.
6. Добавьте созданный каталог в Codex как отдельный сохранённый проект. Создавайте
   семь role-задач только внутри него.
7. Полностью перезапустите Codex, чтобы он получил окружение и перечитал проектную
   конфигурацию.
8. В начале новой задачи вызовите `ba_get_agent_workspace_manifest` и проверьте
   ожидаемые `project.id` и `project.slug`.
9. Только после успешной проверки всех семи ролей отзовите в Planner старые
   одиночные/общие токены этого проекта и перестаньте использовать прежние
   projectless-задачи. Их история сохранится, но конфигурация проекта к ним
   автоматически не добавится.

Ожидаемые границы:

| Проект | `project.id` | `project.slug` |
| --- | ---: | --- |
| AnalystCraft | 10 | `analystcraft-2` |
| HireWire | 29 | `hirewire` |

Если manifest вернул другой проект, работу необходимо остановить. Сервер также
отклоняет явный запрос к проекту, который не совпадает с привязкой токена, с
ошибкой `MCP_PROJECT_SCOPE_MISMATCH`.

## Безопасность

- Не добавляйте `~/.codex/.env` или значения токенов в Git.
- Не используйте один токен для разных ролей, проектов или устройств.
- При потере устройства отзовите только его токены в настройках ContentOps Studio.
- Не передавайте `projectId` другого проекта в обход manifest: сервер отклонит запрос.
