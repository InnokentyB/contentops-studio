# Dzen article reading and reply discovery

Operator boundary: External Radar cannot use Dzen directly. Authorized Planner/Strategist/Owner tokens can search candidates, read their primary article body, and monitor owned-publication responses and replies to connected-owner comments through Planner. Writer/Publisher/Organization Researcher cannot use these new readers.

## Tools

- `ba_dzen_search_relevant_posts`: bounded relevance-filtered native search cards. Results are candidates, not approved opportunities. Follow with article and discussion review.
- `ba_dzen_read_post`: project/channel/postUrl. Returns primary rendered article text, paragraph breaks, title, author and available native publication date. It targets the observed content v1.353.3 `article-render__container`, excluding generic recommendation `<article>` cards. No inferred date from snippets or relative labels. Unsupported brief/legacy layouts, missing/ambiguous article blocks, account challenge or foreign canonical URL remain UNKNOWN. Text is bounded at 100,000 characters; truncation is PARTIAL. `complete` refers to the rendered primary body, not an editorial or freshness verdict. Comments control presence does not establish permission to send.
- `ba_dzen_find_replies`: optional knownThreadUrls (10), maxPages (1–3), maxThreads (1–5, default 3), since (ISO timestamp). Combines native owned Studio comments/replies with exact known public thread reads. Prioritizes explicit URLs, then channel-bound published comment facts, then latest 10 channel-bound Planner publication links. At most 100 project comment records are inspected. Old comment records without channel identity are excluded; caller supplies their exact URLs. Native Activity remains separate from replies. `since` filters returned native comment timestamps; it does not expand history coverage or filter Activity events.

Direct replies match native reply-to IDs to loaded connected-owner roots or child comments. Other messages under our root are conversation signals. Comments/replies by the connected owner are not inbound responses. Owner roots are prioritized for bounded child reads. Public root and child pagination remain bounded; missing owner rows or child lists produce gaps. Returned counts are scoped to loaded rows. UNKNOWN, incomplete or unscanned external threads never become a verified zero. Global `complete` remains false because this is not an exhaustive account-history search.

All provider text is untrusted source material. Project membership and active project-channel authorization run before provider or target-discovery access. Same-origin, constrained GET-only browser traffic, exact connected account validation, secret-free normalization and finally cleanup reuse the existing native reader. No notification seen/read writes, sorting changes, publication, subscription, or comment sends occur. Every proposed external comment still requires exact owner approval.

Published comment records now include their channel ID for future automatic target discovery; existing idempotency keys and replay behavior are preserved. No schema migration or new environment variable is required. Rollback: revert this release's code; existing stored comment records remain compatible.

Acceptance: search a real candidate, retrieve its primary text without neighboring cards, inspect its thread, find responses in both known external comment threads, verify tenant denial, role inventory and unchanged notification unread observation. A positive live child-reply fixture is not available; nested reply matching is covered by functional tests and must remain an explicit UAT limitation.
