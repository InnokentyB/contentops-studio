# Автопубликация в Дзен

Планер публикует материалы в Дзен через изолированный headless-браузер. Публичного API создания публикаций в текущем контуре не используется.

## Подготовка Railway

1. Добавьте в сервис `planner-app` переменную `CHANNEL_SECRETS_KEY` со стабильным случайным значением:

   ```bash
   openssl rand -base64 48
   ```

2. Не меняйте это значение после сохранения сессии Дзена: старые данные перестанут расшифровываться.
3. Перезапустите `planner-app`.
4. Убедитесь, что Railway-образ содержит Chromium из зависимости Puppeteer и может обращаться к `https://dzen.ru`.

## Подключение канала

1. Войдите в нужный аккаунт Дзена в отдельном браузерном профиле.
2. В планере откройте `Настройки проекта → Каналы → Zen (Dzen)`.
3. Укажите внутреннее название, ID или slug канала и режим работы.
4. Вставьте строку Cookie из авторизованного запроса к `dzen.ru` и сохраните канал.
5. Снова откройте канал и нажмите `Проверить подключение к Дзену`.

После сохранения строка сессии шифруется. API и интерфейс возвращают только маску `******`.

## Поведение публикации

- `article` открывает редактор статьи и требует заголовок.
- `post` открывает редактор короткого поста.
- Если в задаче задано изображение, публикация считается неуспешной, пока изображение не загружено.
- Успех фиксируется только после получения новой публичной ссылки вида `dzen.ru/a/...`, `dzen.ru/b/...` или `dzen.ru/media/id/...`.
- MCP-команда `ba_execute_delivery` обязана вызывать task-native publisher и не может выставить `delivered` самостоятельно. Терминальный успех разрешён только после появления канонического `PublicationFact` с публичной ссылкой или provider object ID.
- Неоднозначная доставка без внешней идентичности получает `verification_required`; повтор через legacy `ba_recover_delivery` запрещён, чтобы не создать ложный успех или дубль публикации.
- Истёкшая сессия, CAPTCHA, изменившийся интерфейс или отсутствие permalink переводят задачу в `browser_required`.
- Фиктивные ссылки и webhook-подтверждения не считаются публикацией.

## Обновление сессии

Если тест подключения сообщает об истёкшей сессии, повторите вход в браузере, вставьте новое значение Cookie в настройках канала и сохраните. Не отправляйте Cookie в чат и не сохраняйте его в Git.
