# Threads API reliability — engineering evidence

Owner approved the five design packets on 2026-10-19. Scope is synthetic implementation; no production credentials, provider calls, migration, capability activation, public push/PR or deploy occurred.

The generic Threads text-only route now optionally creates an additive API recovery row alongside the delivery attempt. Durable CAS phase fences precede create/publish; validated container and post IDs persist before subsequent operations. A lost publish response never authorizes another POST. The original duplicate-history policy and historical image/chain/exact-task routes remain unchanged.

`ba_reconcile_threads_publication` uses authenticated Owner/Publisher capability routing and normal owner/tenant/package/release checks. Its transport has only known-object/profile GET operations, a 1MiB response cap, redirect refusal and deadline/cancellation. Profile identity is checked before object GET. Text, numeric object ID, account, top-level TEXT form, canonical URL and provider timestamp must match the original immutable snapshot. Missing original post ID remains a held gap; no history similarity is promoted into fact authority. Container-status reading remains unimplemented/unadmitted because the current official contract could not be verified.

Read budgets and leases persist across calls: at most three rounds, twenty reserved requests and 180 seconds. A normal call can automatically retry transient GET failures at the persisted intervals; cancellation stops continuation. Process death does not install an unattended startup sweep. Finalization uses the canonical fact service and one transaction for attempt/recovery/fact/audit. Persisted API holds survive admission rollback and block arbitrary generic fact callbacks. A last commit check includes cancellation, generation, deadline AND the original recovery lease expiry.

`THREADS_API_RECOVERY_ENABLED=false` remains the default. A new additive migration is required before separate live admission. Disabling admission retains historical rows and holds; it never resets uncertain attempts.

The touched generic release no longer hardcodes a project/slug. Owner membership, manifest tenant equality/checksum and exact channel/revision/body/schedule/account/release guards remain. Independent root review approved removal of exactly two obsolete runtime-policy baseline rows (`00c9ee…` and `e2d08…`, count one each). Findings/baseline reduce from 7096 to 7094; no scanner exception or new debt was admitted.

Required checks run only inside reviewed Docker images; PostgreSQL is separate synthetic state on internal subnet `10.231.83.0/28`, without published ports. See compose.verification.yaml and TRUN.yaml. Keep its named synthetic volume; stop with compose down, never down -v. A separate preview-only synthetic database was created for root's independent preview tests, so do not stop the shared synthetic DB until that verification completes.

Evidence records both positive runs and corrected failures. Initial phase RED: three tests failed for absent persistence hooks. Later regressions found numeric-ID validation had affected historical chain/reply fixtures; validation was limited to the newly admitted journal route, preserving old behavior. Adversarial PostgreSQL RED caught a lease expiring immediately before commit; the new final fence rolls back all canonical writes. Reader RED caught both an oversized valid JSON response and missing redirect refusal.

Engineering evidence is not owner UAT or proof of real account permissions. Automatic recovery is intentionally limited to newly journaled, known-post-ID generic text publications. Legacy attempts, large-history preflight blockers, missing-ID correlation and other publication forms remain explicit limits.

Root independent review additionally required bounded JSON and redirect refusal, exact original schedule/decision/visual-package rechecks, and a full-database-outage error that does not claim the post ID was saved. New causal RED tests cover each. A package changing after dispatch now retains its historical observed ID under original-attempt CAS but cannot obtain a fact or new send authority. Provider protocol verification against the [Meta-owned collection](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api?entity=request-34203612-74fb48b1-ad1a-480e-b200-4dcdb8126a2f) established that published objects use `TEXT_POST`, distinct from the create parameter `TEXT`.
