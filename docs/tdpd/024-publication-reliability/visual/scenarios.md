# REL05 final scenarios and bounded protocol

Owner explicitly approved the REL05 LOCK/QAR/ARCH/RISK before these scenario tests. Source baseline3fd625a. The design document's historical proposed heading is retained as the original approval packet; root coordination holds the subsequent owner approval.

Scenarios executed through installed SDK and isolated PostgreSQL: generic command discovery/validation; unchanged accepted-copy preview without writes; apply retaining old active decision/completed WI and opening fresh WI; exact idempotent replay/changed packet rejection; stale body/version/channel/date/owner rejection; any delivery attempt/uncertainty denial; identical concurrent request deduplication; disabled project pipeline remains blocked; old decision asset callback and old WI callback cannot revive readiness; required-mode no-visual rejects; current art lease+source decision; independent current review lease/generation; request-vs-claim in both orders; transaction rollback. Additions follow the approved completion clause, not new provider scope.

The new optional `workItemId`, `leaseToken`, `reassessmentGeneration` fields on `ba_review_image_asset` are mandatory only when a server-owned reassessment request governs the asset. They prove a separately claimed `visual_review` work step carrying the current asset and decision IDs. No new distinct-person restriction is added: the same authenticated Owner may perform separate authorized stages. The request is fulfilled in the same transaction as approved current asset selection and review completion. Generation and request WI are resolved from immutable `WorkflowEvent`, never trusted from caller JSON. Existing calls unrelated to reassessment retain the prior protocol.

No schema migration/new publication fact storage. Content-row lock serializes request/art/callback writes. Request changes status to `approved`; existing direct-dispatch status CAS (`planned`/`ready_for_execution` -> `publishing`) cannot claim the old package after commit. If claim wins first, request rejects `publishing`. Existing browser and provider release guards revalidate visual state/mode/current exact decision and cannot admit the pending package. New reassessment rejects any existing attempt, connector dispatch job, related execution work, release projection or non-prepublication authority mode. It never cancels these records or recalls a physical submit.

No provider calls, image fetch/generation, production tokens/database, public push/PR, deployment or live UAT authorized. Synthetic source URLs use example.invalid and are only recorded as fixture strings.

A narrow shared lifecycle guard now rejects generic completion for reassessment art/review WIs, explaining the proper art-decision or asset-review command. No generic cancel operation was found in this lifecycle module. Generic block is a separate operator action and remains an explicit blocked state; it never fulfils the request or grants send authority.

Source attachment adds optional `decisionId` and `reassessmentGeneration`, required only for a governed reassessment. They are checked before ingestion and again under the content lock, preventing a late old source callback from silently attaching old bytes to the new active decision. Generate/source/review work contexts expose the server-owned generation.

Final canonical-writer audit reproduced an actual MCP race: an old content_write completion could pass the old request check, pause before pipeline settings, let the new Owner request commit, then overwrite accepted copy and clear acceptance. Both operations committed in RED. `markRevisionStale` now acquires the tenant content-row lock and reloads the item before testing the request. The deterministic race observes either Owner completion or a real PostgreSQL FOR UPDATE lock wait, then requires exactly one operation to commit. Art/review generic completion takes content before consuming its WI; legacy content_write has already reserved its own distinct writer WI, while reassessment/art/release paths do not lock that writer WI, avoiding a cycle in this tested boundary. No global deadlock-freedom claim is made.

Final authoritative-boundary RED: restoring only mutable no-visual content projections while leaving the new immutable request and art WI in place still admitted an actual browser release in the prior implementation. The shared `assertVisualReassessmentReady` helper reads durable request authority and requires exact current required visual, current decision and matching independent-review fulfilment audit/asset binding. It throws `PUBLICATION_VISUAL_REVIEW_REQUIRED` with a static correction.
