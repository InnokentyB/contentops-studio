# REL05 implementation and operator boundary

Owner-approved design is implemented as an internal Owner MCP operation, `ba_request_publication_visual_reassessment`, with preview/apply. No task/account-specific production code, database migration, provider send, image generation, production mutation, public push or deployment. The only baseline change is the root-reviewed deletion of one obsolete protocol-enum falsepositive, documented in scenarios.md; no scanner exemptions or admitted new findings.

An immutable server-authored WorkflowEvent binds a fresh art WI, generation, accepted revision/body digest, channel/placement/schedule and new Owner instruction. Apply locks and CAS-checks the content row, preserves accepted copy and old decision/WI history, sets required/PENDING_ASSESSMENT/blocked and status approved. Existing delivery attempt, executor, connector job, release authority, current visual consumer or conflicting request denies the operation. Exact replay returns the recorded result; changed replay rejects. Serializable retry is bounded to three transactions and recognizes only known Prisma conflict P2034 or raw P2010 SQLSTATE40001, including the observed driver-adapter code path. Unknown errors are not retried or echoed.

Canonical art completion must use the current generation's art WI and actor-bound lease. Required Owner visuals reject NO_VISUAL_NEEDED with an Owner-instruction-specific explanation, rather than pretending the channel placement intrinsically requires an image. Context and downstream generate/source/review WIs expose the new instruction/generation. Source completion checks explicit current decisionId and reassessmentGeneration before ingestion and again under the content lock. Generation/asset/review callbacks verify the current request/decision/package and cannot reopen a released, started or published package.

Image review reloads and binds the current asset under the content lock. The existing checked update/cancel/response expressions use this refreshed record; a deterministic stale-URL race verifies no pre-lock cached URL can approve the asset. A separate current visual_review WI lease and request generation are mandatory only for reassessments. Completion audit, current asset selection and review-WI completion share one transaction. Independent review is a separate authorized step, not a newly imposed distinct-person restriction.

Generic completion cannot consume an art/review WI without its typed result. Lease release/reclaim remains supported and is tested before normal typed assessment. Generic block is a separate explicit blocked state and does not fulfil the request or grant send authority. No automatic cancellation, replacement lease, fresh publication attempt or retry after uncertainty is introduced.

The explicit requirement survives project pipeline-off settings. It is fulfilled only by the current decision and independently reviewed current durable asset. Later ordinary revisions may leave the completed historical request behind; a pending request cannot silently drop its frozen accepted package. A completed review remains readable through readiness/history; repeating a consumed review lease is rejected rather than creating another review event.
