The approved narrow packet is implemented. This is a self-review, not an independent security review or Owner acceptance. Source is isolated from PR201; no production code/config/data was changed by these local tests.

The generic service still checks current Owner membership/manifest/revision/body/visual/schedule/identity/release and existing attempts/facts, creates durable custody before provider dispatch, and freezes uncertainty. A Threads-only release key on another provider is explicitly rejected, not ignored. No API/browser transport fallback or Registry-only authorization was added. Existing browser-primary policy and separately authorized API use stay intact.

It can describe active preparation only for exactly one error-free pending attempt, one matching work/revision, matching original actor/key/start audit, complete bounded event inventory without recorded permit/dispatch/uncertainty, and the active original actor-bound lease. Expired/missing lease ownership produces a precise same-attempt recovery action. Real errors, permits, dispatch, missing/malformed/capped history, conflicting attempts and persisted recovery retain conservative reconciliation. Facts remain read-only. Internal attempt keys and lease actors are explicitly omitted from safe result projections; leases and provider errors are not exposed.

## Release and rollback

No migration is expected. Public code, PR and production rollout require separate authorization because the accepted packet explicitly covers local work only. Before any later release, reconcile current main, run CI on the exact public head, obtain fresh backup/restore evidence and check both Railway services. Retain fact/attempt/lease/audit history and current secrets on rollback. Do not replay stored operations or interpret a lost response as rollback. A runtime rollback restores code only; Owner/provider UAT remains explicit.
