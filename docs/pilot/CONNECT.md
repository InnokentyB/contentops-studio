# ContentOps: подключение своего агента

Планнер помнит, агент думает.

Вы подключаете своего ИИ-агента (Claude, Cursor, Codex, Cline — любого, кто умеет MCP)
к общей операционной базе. Агент получает инструменты, чтобы читать состояние вашего
проекта, вести инициативы, назначать темы недели и раскладывать неделю на задачи.
Тексты, идеи и картинки агент по-прежнему делает сам, на вашей стороне и на ваших
лимитах. Планнер хранит структуру, даты, статусы и историю — то, что агент забывает
между чатами.

На пилоте это бесплатно.

---

## 1. Получить доступ

Два пути, оба дают одно и то же.

**Сами:** зарегистрируйтесь в планнере, откройте `Настройки` → `MCP`, выберите карточку
**Стратег**, нажмите «Создать доступ». Токен показывается **один раз** — скопируйте сразу.

**От ведущего:** получите карточку с адресом, токеном и сроком действия.

Понадобится три значения:

| Что | Пример |
|---|---|
| Адрес | `https://<ваш-сервер>/mcp/strategist` |
| Токен | `mcp_XXXXXXXXXXXXXXXXXXXXXXXX` |
| Заголовок | `Authorization: Bearer <токен>` |

Токен привязан к вам и к вашему проекту на сервере. Подменить проект параметрами вызова
нельзя — чужие данные вы не увидите при всём желании.

---

## 2. Подключить агента

Интерфейсы клиентов меняются от версии к версии. Если названия пунктов разошлись,
ориентируйтесь на суть: удалённый MCP по HTTP, адрес профиля, заголовок `Authorization`.

### Claude (приложение)

`Settings` → `Connectors` → `Add custom connector`. Укажите адрес профиля и bearer-токен.

### Claude Code

```bash
claude mcp add --transport http contentops https://<ваш-сервер>/mcp/strategist \
  --header "Authorization: Bearer mcp_ВАШ_ТОКЕН"
```

### Cursor

`~/.cursor/mcp.json` (или `Settings` → `MCP` → `Add new server`):

```json
{
  "mcpServers": {
    "contentops": {
      "url": "https://<ваш-сервер>/mcp/strategist",
      "headers": { "Authorization": "Bearer mcp_ВАШ_ТОКЕН" }
    }
  }
}
```

### Cline / VS Code

В `cline_mcp_settings.json`:

```json
{
  "mcpServers": {
    "contentops": {
      "type": "streamableHttp",
      "url": "https://<ваш-сервер>/mcp/strategist",
      "headers": { "Authorization": "Bearer mcp_ВАШ_ТОКЕН" }
    }
  }
}
```

### Codex и всё остальное

Если клиент умеет только stdio, поставьте мост:

```bash
npx -y mcp-remote https://<ваш-сервер>/mcp/strategist \
  --header "Authorization: Bearer mcp_ВАШ_ТОКЕН"
```

и пропишите эту команду как обычный stdio-сервер в конфиге вашего клиента.

## 3. Проверить, что связь есть

До всякого агента, прямо в терминале:

```bash
curl -s -X POST https://<ваш-сервер>/mcp/strategist \
  -H "Authorization: Bearer mcp_ВАШ_ТОКЕН" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Ответ со списком инструментов `ba_*` означает, что всё в порядке.

Потом в новом чате с агентом:

```
Прочитай bootstrap рабочей области ContentOps, перечисли доступные инструменты
и опиши текущее состояние моего проекта. Ничего не меняй.
```

---

## 4. Что профиль «Стратег» умеет и чего не умеет

**Умеет:** читать рабочую область и её обновления, смотреть каналы, задачи публикаций
и факты публикации, вести инициативы и связи между ними, назначать тему недели,
раскладывать неделю на семь датированных задач, двигать сроки, проверять покрытие плана
и готовность к релизу, читать операционный календарь и метрики.

**Не умеет:** публиковать в канал, переписывать готовый текст публикации, генерировать
что-либо на сервере. Это сделано намеренно: на пилоте ни один агент не может отправить
пост в живой канал и не может потратить ничьи ключи, кроме ваших собственных.

**Заводится в интерфейсе, не через агента:** каналы. Инструмента создания канала в MCP
нет, поэтому первый канал добавьте руками в `Настройки` проекта — дальше он понадобится
агенту как `channelId`.

---

## 5. Правила обращения с токеном

- Один человек, одно устройство, один токен.
- Не вставляйте токен в промпт, скриншот, документ или репозиторий. Он нужен клиенту в
  конфиге, а не агенту в переписке.
- Потеряли устройство или закончили работу — отзовите доступ в `Настройки` → `MCP`.
  Передеплой не нужен, отзыв действует сразу.
- У пилотных токенов есть срок. После него подключение просто перестанет отвечать.

---

## 6. Если не подключается

1. Адрес заканчивается на `/mcp/strategist`, а не на `/mcp` и не на `/health`.
2. Токен вставлен целиком, без пробелов и переносов, и передаётся как
   `Authorization: Bearer <токен>`.
3. Профиль в адресе совпадает с профилем токена. Токен от `strategist` не откроет
   `/mcp/planner`.
4. Доступ не отозван и не истёк — видно в `Настройки` → `MCP`.
5. `401` означает проблему с токеном, `404` — с адресом. Это разные починки.
